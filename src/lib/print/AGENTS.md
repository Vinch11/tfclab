# Print / export rules

- Décision coach explicite (2026-10-22) : `openPrintableHTML` ne génère **jamais** de fichier PDF par l'application, sur aucune plateforme. Le parcours est toujours : ouvrir une page HTML dédiée affichant l'intégralité du document, puis un bouton "Imprimer / Enregistrer en PDF" qui déclenche l'impression native du navigateur.
- Décision coach explicite (2026-10-22, correction suivante, suite à un retour de PDF **entièrement vide** à l'impression sur PC) : cette "page dédiée" n'est plus une `blob:` URL ouverte via `window.open()`, ni (pour iOS) une surcouche iframe plein écran — c'est désormais une VRAIE page du site, `/print-preview` (`src/pages/PrintPreviewPage.tsx`), chargée par une navigation NORMALE (même origine, aucune `blob:`). Le document est relayé via `sessionStorage` (`openPrintPreviewDocument` dans `openPrintableHTML.ts`) ; `PrintPreviewPage` le lit et remplace le document courant par celui-ci (`document.write`), puis l'utilisateur imprime nativement — même mécanisme sur desktop ET iPhone, un seul code pour les deux.
- Pourquoi ce changement : une `blob:` URL n'est valable que dans le contexte du document qui l'a créée ; sa fiabilité face à l'impression RÉELLE et interactive d'un navigateur (Ctrl+P → aperçu → "Enregistrer en PDF") n'est garantie par aucune spécification. Un test automatisé utilisant `page.pdf()` (API CDP `Page.printToPDF`, seul mécanisme qu'un outil de test peut déclencher) ne reproduit PAS ce bug même sur une `blob:` URL — ce qui a été vérifié empiriquement pendant l'investigation et exclut ce type de test comme preuve de fiabilité pour ce mécanisme précis. D'où la bascule vers une navigation normale, servie par l'application comme n'importe quelle autre page (même principe que le bouton "Imprimer" déjà robuste de `CoachChecklistPage`), qui élimine cette classe de risque à la source plutôt que de la contourner.
- Historique (pour comprendre le code existant, pas pour y revenir) : avant la première décision, iOS passait par une génération PDF réelle sur l'appareil (html2canvas + jsPDF, `iosPdfExport.ts`, supprimé) — motivée par l'échec de plusieurs mécanismes d'impression native (document.write : pagination qui explose ; navigation blob: HTML : onglet qui n'affiche que l'entête). Entre les deux décisions, une surcouche iframe plein écran (`openInlineOverlay`) a existé — elle aussi supprimée, remplacée par `/print-preview`.
- `EMBEDDED_PRINT_ONCLICK` (utilisé par les builders qui embarquent leur propre bouton "Imprimer" dans le HTML généré) vaut désormais simplement `"window.print()"` : le document est toujours la fenêtre top-level, plus aucun détour n'est nécessaire.
- Si un nouveau souci de pagination ou d'impression apparaît : corriger `PrintPreviewPage.tsx` / `openPrintPreviewDocument` dans `openPrintableHTML.ts`, jamais réintroduire une `blob:` URL, une iframe de surcouche, ou une génération de fichier PDF par l'app — ce sont désormais des règles explicites du coach, pas des préférences techniques.
- Test de non-régression obligatoire pour ce mécanisme : `e2e/print-plan-export.spec.ts` (Playwright, Chromium réel, `page.pdf()` + extraction de texte via `pdfjs-dist`) — valide qu'un document ouvert via `/print-preview` produit un PDF non vide contenant la première semaine, la dernière semaine et la dernière séance, y compris pour un plan de pagination longue (34 semaines).
