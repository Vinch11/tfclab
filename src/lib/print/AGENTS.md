# Print / export rules

- Décision coach explicite (2026-10-22) : `openPrintableHTML` ne génère **jamais** de fichier PDF par l'application, sur aucune plateforme. Le parcours est toujours : ouvrir une page HTML dédiée affichant l'intégralité du document, puis un bouton "Imprimer / Enregistrer en PDF" qui déclenche l'impression native du navigateur. Sur desktop : nouvel onglet (blob: URL) + `Ctrl+P`. Sur iOS : surcouche plein écran interne (`openInlineOverlay`, même document HTML, bouton Imprimer dédié qui appelle `window.print()` sur la fenêtre top-level).
- Historique (pour comprendre le code existant, pas pour y revenir) : avant cette décision, iOS passait par une génération PDF réelle sur l'appareil (html2canvas + jsPDF, `iosPdfExport.ts`, supprimé) — motivée à l'époque par l'échec de plusieurs mécanismes d'impression native (document.write : pagination qui explose ; navigation blob: HTML : onglet qui n'affiche que l'entête). La surcouche interne a depuis été fiabilisée indépendamment de cette génération (mesure de hauteur correcte, scale neutralisé avant impression) : elle n'a donc plus besoin de ce détour.
- Si un nouveau souci de pagination iOS apparaît : corriger la surcouche (`openInlineOverlay`/`doPrint` dans `openPrintableHTML.ts`), jamais réintroduire une génération de fichier PDF par l'app — c'est désormais une règle explicite du coach, pas une préférence technique.
