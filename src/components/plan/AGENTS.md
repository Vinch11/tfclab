# QA review/export rules
- HumanCoachReview inspects the immutable saved plan and verifies its full hash against the server binding; decisions and unresolved blockers are saved by the authenticated server only. Why: ordinary review is not scientific attestation or export consent.
- QA planning uses the actual coach DET adapter only for qualified inputs and retains IA's existing prevalidation/generation path; both retain provenance through the common append-only saver. Why: a selector must not load a synthetic fixture or silently fall back.
- The normal coach DET flow (`AthleteDetSimplePanel` via `src/lib/det/athleteDetBridge.ts`) prefills only app-record values with origin/date, asks measured-vs-estimate per value, and reuses the pinned family pool (`familySourcePools.ts`, engineering CI admission, never scientific review) with two deduplicated athlete checklists; `coachReviewedSource`/brick approvals come only from a real per-source review row (same coach+athlete+fingerprint), else DET is blocked with an upstream review task; no coach limiter order without explicit reorder. Why: CI pool admission and athlete checks are not human source review.

- Reusable source-content reviews may come from an explicit human action in LibrarySourceReview, bound to the full source/dose manifest and coach. They never supply athlete checks: bindLibraryReview requires current explicit answers and the bridge invalidates a changed answer set/family/profile. No scientific or prescription authority; candidate SQL is not applied by the app.

- `NolioMultisportPreparation` requires deliberate per-brick choice plus explicit representation/time confirmation, then creates a new owned version through the common append-only saver with exact readback. It never mutates the parent version, invokes a sender, or carries coach-review/export authority to the new version; changing the displayed version clears all drafts.

- The simple panel starts with a read-only `DetPlanningDraft` study from the shared profile before the detailed review controls. It lists candidate sources, never a qualified dose or a saved/exportable plan; invalidating the profile/negative restrictions discards the study. No human check is prefilled or transferred from this preview to the strict generation path.
- The primary pre-review action is now `V3PlanGeneration`: it displays the separate chosen-source proposal with complete configured blocks. `DetPlanningDraft` remains folded as alternative-source inspection. Both discard changed profiles/restrictions; V3 generation rechecks coach/athlete identity after calculation. No proposed block, unknown timing or source-content review becomes a qualified outcome by display.

- Normal planning now uses the page’s common Generate button for IA and qualified DET, with the panel registering its generation action and reporting busy state. DET checks are expandable; remove proposal/local-save actions from this normal path. Accepted DET outcomes use the existing common viewer/save/history, preserve provenance and never fall back to IA. Await installation prevalidation and invalidate pending installation when panel context changes. This supersedes the earlier primary-proposal UI rule at the user’s explicit request.
