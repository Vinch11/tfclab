# TFCLab finalization — 8 November 2026

This branch combines the latest Nolio resume/delayed-read fixes from #464,
the contextual 920-source integration from #465, and the corrections below.
It is a reviewable integration candidate, not proof of a deployed application,
independent sporting validation, completed Nolio delivery or watch guidance.

## 1. Nolio export

New normal DET plans freeze `_nolioV2TargetFormat: pace-v1`. The shared
preparation used for simulation, sending and verification serializes pace
targets as raw `/km` or `/100m` strings. Decimal source seconds are retained;
running speed targets are inverted into pace bounds without whole-second
rounding. Power, dose, repetitions, RPE and brick composition are unchanged.
The raw-target schema in the retained official read contract permits string
pace values. Provider acceptance of fractional seconds still requires an
authenticated dry-run; offline validation is not that evidence. The existing
automatic simulation gate must succeed before any create.

Existing immutable archives do not acquire the format field: their m/s bodies,
operation keys and saved receipts remain unchanged. Unknown formats fail
preparation. Scoped exports retain the same per-operation body as whole-plan
preparation. Exact readback still rejects changed units and missing, collapsed
or altered bounds; no new provider-equivalence tolerance is introduced.

Read-only QA database check on 8 November: the latest 12-week version still has
94 latest `VERIFIED_UNIQUE / exact_unique` operation receipts and one
`UNKNOWN / read_failed` receipt. No new success receipt was manufactured. The
101/101 earlier calendar-conflict precheck was not a delivery count.
The QA preview loads the app's coach sign-in page in the available browser.
No coach session, provider credential or private Nolio API access was borrowed.

## 2. Shared athlete input

Generation continues to use the existing frozen app planning input and its
original diagnostic priorities. The imported source filters preserve known
athlete level, event, phase, negative restrictions, source blockers and recovery.
No new diagnostic or athlete data is invented. Source affinity remains distinct
from exact physiological dose and an actual training adaptation.

## 3. Source diversity

The existing 800-source cohort and strict qualified pools remain intact.
The additional registry accounts for all 920 rewritten records: 826 ordinary
records, of which 661 pass source engineering checks and 165 remain blocked,
plus 94 records requiring specialist routing. Normal generation enables the
contextual imported alternatives. New recipes retain the solved sport,
primary domain, duration, zone ledger and original limiter matches, without
adding missing anchors or breaking source recovery. The previous native
rotation and real exercise deload corrections are retained.

Specialist records are not represented as ordinary ready workouts. No source,
scientific or athlete approval is generated by registration or selection.

## 4. Coach journey

The common Generate / save-history-reopen / Export journey remains in place.
The one-click export controller retains automatic simulation, conflict checks,
bounded create batches and durable readback. Old uncertain activities are never
automatically resent. Production main and the isolated QA deployment have not
been changed by this branch.

## 5. Preparation projects

New normal plans retain the shared weekly quotas expected by the common viewer.
The project timeline in the viewer and printable PDF reads the fingerprint-bound
saved V3 proposal, so reopening an old archive does not require regenerating
it or reading the current athlete. It shows actual consecutive development,
recovery, taper and race periods, the saved primary/complementary priorities,
key/long-session source associations, selected source titles and known exercise
minutes. Missing total time remains missing. A zero-match focus stays visible
as zero; affinity counts never certify dose or improvement. PDF labels are
HTML-escaped and session prescriptions are left unchanged.

## Acceptance still required

The signed-in normal coach flow must simulate the new target format, finish
and uniquely reread every expected Nolio activity, preserve the two legs of
each brick, and verify the resulting watch guidance. The earlier partially
exported plan must be verified/resumed as its original version, rather than
replaced with a newly generated version on the same occupied dates.

The new code is not deployed by this report. Publishing and sporting approval
are separate from the local and hosted checks recorded with its pull request.
